# File upload test cases

Run these in a test environment with an account that can upload files. Prepare a valid file, a zero-byte file, and files one byte below, exactly at, and one byte above the configured size limit.

| ID | Scenario | Steps | Expected result |
|---|---|---|---|
| UP-01 | Upload a valid file | Upload a small file of an allowed type. Refresh the page, then open or download it. | The upload succeeds. Exactly one file appears after refresh, and its contents match the original. |
| UP-02 | Enforce the size limit | Upload valid files one byte below, exactly at, and one byte above the limit. | Assuming the maximum is inclusive, the first two succeed and the third is rejected with a size-limit message. |
| UP-03 | Reject an unsupported type | Upload a file of a disallowed type. | The upload is rejected with an actionable message. No file appears after refresh. |
| UP-04 | Check disguised file content | Rename a disallowed file to use an allowed extension and submit it directly to the upload endpoint. | If the feature restricts file types, the server rejects the disguised file and creates no accessible attachment. |
| UP-05 | Handle a zero-byte file | Upload a zero-byte file with an allowed extension. | The result follows the product’s empty-file policy. If rejected, the user sees a clear message and no attachment is created. |
| UP-06 | Handle real-world filenames | Upload an allowed file named `résumé final (2).pdf`, using an allowed extension. | The filename displays correctly and the downloaded contents match the original. |
| UP-07 | Recover from a dropped connection | Start an upload and disconnect before the transfer finishes. Reconnect and retry. | The failure is visible. The retry succeeds, leaving one complete attachment and no partial file. |
| UP-08 | Handle a lost response | Let the server finish the upload, then drop the response before the client receives it. Retry the same upload. | The final state follows the duplicate policy, and the interface accurately reflects what was saved. |
| UP-09 | Cancel an upload | If cancellation is supported, start a slow upload and cancel before it completes. Refresh the page. | The upload stops and no attachment appears after refresh. A new upload can still succeed. |
| UP-10 | Enforce upload permissions | Submit an upload directly to the server as an account without upload permission. | The server rejects the request and creates no attachment. |
| UP-11 | Enforce file access permissions | For private uploads, try to open the saved file as another account without access. | The request is denied and no file contents are returned. |
| UP-12 | Upload with a keyboard | Use only the keyboard to select and submit a file. Repeat with an invalid file. | The controls are reachable and operable, and both the success and error states are communicated. |
